# Tools4Us

Turkish-first, unofficial guide that helps Turkish Cisco partners pick current Cisco models and learn about new Cisco features. Static site on GitHub Pages. Owner and only editor: Denis.

The full spec is `docs/SPEC.md`. Before planning any task, read the SPEC.md sections that the task touches. If the spec and your assumptions disagree, the spec wins. If the spec is silent or contradicts itself, ask instead of guessing.

## Hard rules
- IMPORTANT: Never show, recommend or feature a model whose `lifecycle` is not `current` (End-of-Sale models appear only with a badge and a replacement link).
- No pricing, ordering, quoting, stock or lead-time features. Ever.
- Turkish is the default language. Every UI string exists in TR and EN. Write plain Turkish for non-technical readers; put the technical term in brackets.
- Content lives in `data/` and `content/`. Never hard-code models, specs or stories in components.
- Every spec value needs `source_url` and `last_verified`. Never invent a spec, date or PID; leave it empty and flag it.
- No Cisco logo, no Cisco or Ingram Micro branding, no assets/code/wording from ciscosizing.com. Footer disclaimer on every page.
- Mobile first: check every page at 375 px wide.

## Repo map
- `docs/SPEC.md`: product spec (source of truth). Launch scope: Switching, Wireless, Routing (Routing includes Meraki MX); other families are "Yakında".
- `docs/Phase1_Dataset_Audit.xlsx`: 348 known data issues with CSV row numbers and fixes
- `docs/old-site/`: the old SelectorTool code, for reference only. Port ideas, don't copy its filter logic (see SPEC "Old site review").
- `data/legacy/`: old CSVs, read-only input to the migration script. Never edit by hand.
- `data/catalog/`: new normalized data, one xlsx workbook per family, edited by hand (seeded in Phase 1)
- `scripts/build-data/`: validator, xlsx reader/writer, JSON emitter, one-time `migrate/`, audit closure, tests
- `docs/Phase1_Needs_Decision.md`, `docs/Phase1_Audit_Closure.md`: what the migration derived or left empty, and what is still open in the audit
- `docs/Phase3_Wireless_Verification.md`, `docs/Phase3_Wireless_Needs.md`: the evidence behind every ready wireless row, and what is still draft
- `docs/Phase4_Switching_*.md`, `docs/Phase4_Routing_*.md`: the same for Switching and Routing (verification evidence and the rows that stay draft)
- `data/glossary.xlsx`: terms for tooltips (TR + EN, with meanings); `src/lib/`: pure logic (model cards, filter engine and panels, selectors, compare, config builder, search, shortlist, migration finder, analytics rules, site settings) with tests; `src/scripts/`: browser glue (shortlist storage, analytics loader); `public/vendor/goatcounter/`: the reviewed analytics script (hash pinned); `scripts/build-data/fill/`: one-off data passes (idempotent, keep for traceability)

## Commands
- `npm run dev`: builds the data (`predev`), then the dev server at http://localhost:4321/tools4us/ (the base path is part of every URL).
- `npm run check:data`: validate the catalog (`data/catalog/*.xlsx`), the TR/EN i18n files and `src/lib/site-config.mjs` (service addresses; warns for every "TO FILL") against `.claude/rules/data.md` and the SPEC build checks. Prints a ready/draft/excluded summary; exits 1 on any error. Must pass before any commit.
- `npm run build:data`: `check:data`, then write the published rows (ready + in scope only) to `src/data/generated/*.json` plus `manifest.json` (sha256 per file). The folder is gitignored.
- `npm run check:design`: WCAG contrast check of every colour pair in `src/styles/tokens.css`; fails below 4.5:1 (3:1 for large text and UI edges).
- `npm run check:dist`: checks the built `dist/` (no dev gallery, disclaimer footer on every page, every internal link carries the base path and points at a page that exists, no third-party requests, external links only to cisco.com or meraki.com in a new tab, no draft or excluded PID anywhere (the three JSON data files per language included), no End-of-Sale model in the selector data or the old-model list, story rules, the request form (required consent box, honeypot, KVKK notice linked, posts only to Web3Forms), no `<form>` posting elsewhere, analytics (only the configured GoatCounter address, the vendored `count.js` equal to its pinned hash, no web address in the site's own scripts); warns while a "TO FILL" is on a page). `DIST_DIR=<folder>` runs it on another folder. Run after `astro build`.
- `npm run check:lighthouse`: mobile Lighthouse (default emulation, simulated slow 4G) on the built `dist/`, served by `scripts/serve-dist.mjs` (gzip, Pages base path). Default: hub, Wireless family, one story; `--all` adds 15 more page types; `--url=/tr/x/` for one page; `--detail` lists failing audits and layout-shift elements; fails below 90 for performance or accessibility. Run after `npm run build`. In Git Bash set `MSYS_NO_PATHCONV=1` or `--url=/...` is rewritten to a Windows path.
- `npm run check:a11y`: axe-core (WCAG 2.1 A/AA) in Chrome via puppeteer-core on 33 page states at 375 px and 32 at 1280 px (65 runs; family pages, filter sheet open, compare table, shortlist with items, selector result, contact form with errors, KVKK notice, 404), plus a Tab walk that reports a stop with no visible focus indicator (a ring on the card around the link counts). Fails on any violation, a JS error or an unexpected HTTP status. `DIST_DIR=<folder>` checks another folder (use a Windows path in Git Bash).
- `npm run build`: `check:design`, `build:data`, `astro build`, `check:dist`. Output in `dist/`. This is what CI runs.
- `npm run test:data`: node:test suite for the validator, glossary, the migration invariants against the real workbooks, the audit closure, the graphics layout maths and the wireless logic (grouping, filters, selector run over every answer on the real catalog, compare, Turkish count suffix), search (Turkish folding, typos, old PID to replacement, no draft PID in the index), shortlist (storage, share link, tampered input, CSV), migration finder, analytics rules and the site settings check.
- `npm run migrate:legacy`: one-time seed of `data/catalog/` from `data/legacy/`. Refuses to overwrite existing workbooks (they are edited by hand now); `-- --force` regenerates them and discards manual edits.
- `npm run audit:closure`: regenerate `docs/Phase1_Audit_Closure.md` and `.csv` from the audit workbook and the catalog.
- `npm run preview`: serve the built `dist/` locally, as Pages will. Run `npm run build` first.
- Dev-only graphics gallery: with `npm run dev`, open `/<base>/tr/dev-gallery/`. It does not exist in production builds.

## Workflow
- Work one phase at a time (SPEC "Build plan"). Start each phase in plan mode.
- Prove work with evidence: command output, build/check results, or a screenshot at 375 px and 1280 px.
- Commit after each working step with a clear message. Never push without asking.
- When a phase ends, update the "Status" section below: what is done, what is left, decisions made.
- When compacting, keep the current phase, the list of modified files and any failing checks.
